# 智能采集质量管控平台

面向数据采集团队的质量管控与效率优化平台。覆盖采集任务编排、抓取结果校验、采集链路监控、数据格式转换、去重比对、异常重试、采集审计与合规管理的完整采集质控链路。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 批量标注复核

标注批次复核链路把「标注记录 - 去重策略 - 人工裁决」串成一条可回执的流程，
前端入口在「采集数据标注」页，去重策略清单会同步展示待复核清单。

### 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/tag/review/batches` | 待复核批次清单，带本批统计与解析到的去重策略 |
| GET | `/api/tag/review/batches/{batch}` | 批次待确认项明细，逐条带业务键与拟保留结果 |
| GET | `/api/tag/review/queue` | 下游入口读取的待复核清单（同 `/api/dedup/review/queue`） |
| POST | `/api/tag/review/submit` | 多条一次提交，逐条回执 |
| POST | `/api/tag/review/confirm` | 整组确认（只处理待复核项） |
| POST | `/api/tag/review/reject` | 只驳回有争议的标注记录 |
| POST | `/api/tag/{id}/decisions` | 单条裁定，供逐条回执与单条查看 |

### 规则

- **批量规模**：单次最多 50 条（`BATCH_LIMIT`），超出会提示拆分批次；同一批复核。
- **待确认项**：由标注记录的「业务键 + 去重策略拟保留结果」生成，拟保留为保留/删除，
  整组确认直接沿用该结论。
- **冲突提示**：同业务键出现相反保留结论、同业务键拟保留记录不一致、同数据记录标签或
  标注类型不一致时标记「冲突待裁决」；冲突时以人工复核结论为准，人工裁定后冲突不再提示。
- **回执幂等**：同一复核回执重复送达只保留第一次的裁定并返回原结果；批次级提交也按整批
  回执去重。
- **并发裁定**：同一条标注记录带版本号校验，两人同时提交只有一人成功，另一人得到
  「已被其他复核人更新」或「已被复核」的说明。
- **驳回语义**：驳回项的复核状态回到「待处理」，`归档标注` 会被拦下，不会被策略自动归档；
  重新「提交复核」后可再次裁定。
- **记录字段**：每次裁定写入标注类型、标签列表、复核结论、复核人、复核时间与复核回执，
  并保留标注版本号，批量处理后仍可按单条查看。
- **去重策略引用**：批次内多条策略时按「已启用 > 待校验 > 草稿 > 已停用」解析，同级取最新；
  引用的策略未启用时，拟保留结果仅作复核参考并给出提示。
